# PRD: 알레르기 검사 자동 분석 및 FHIR 변환 시스템

## 1. Introduction/Overview

본 시스템은 알레르기 검사 결과 이미지(SPT/MAST)를 자동으로 분석하여 국제 의료정보 표준인 HL7 FHIR 형식으로 변환하고, 환자 맞춤형 알레르기 관리 리포트를 생성하는 통합 솔루션입니다.

**문제 정의:**
- 알레르기 검사 결과지를 수동으로 입력하고 해석하는 데 많은 시간과 노력이 소요됨
- 검사 결과와 실제 환자 증상 경험 간의 연결이 체계화되지 않음
- 표준화된 의료 데이터 형식으로의 변환이 어려움
- 환자별 맞춤형 관리 계획 수립에 전문 지식이 필요함

**목표:**
OpenAI GPT Vision API를 활용한 OCR 처리와 GPT 기반 대화형 증상 수집을 통해 알레르기 검사 결과를 자동으로 분석하고, HL7 FHIR 표준 형식으로 변환하며, 개인 맞춤형 알레르기 관리 리포트를 생성하는 시스템 구축

## 2. Goals

1. **자동 데이터 추출**: GPT Vision API를 통한 99% 이상의 OCR 정확도 달성
2. **표준화된 데이터 변환**: HL7 FHIR R4 표준에 완벽히 부합하는 리소스 생성
3. **지능형 증상 매칭**: 검사 결과와 실제 증상 경험을 연결하는 대화형 인터페이스 제공
4. **맞춤형 리포트 생성**: 환자별 특성을 반영한 한국어 알레르기 관리 계획 자동 생성
5. **사용자 친화적 인터페이스**: 의료진과 환자 모두 쉽게 사용할 수 있는 Streamlit 기반 웹 UI 제공

## 3. User Stories

1. **의료진으로서** 알레르기 검사 결과지를 업로드하면 **자동으로 데이터가 추출되고 구조화**되어 시간을 절약할 수 있다.

2. **환자로서** 내 검사 결과에 대한 **실제 증상 경험을 대화형으로 입력**하여 더 정확한 진단을 받을 수 있다.

3. **의료진으로서** 검사 결과를 **국제 표준 FHIR 형식으로 자동 변환**하여 다른 시스템과 호환성을 확보할 수 있다.

4. **환자로서** 나의 검사 결과를 바탕으로 **개인 맞춤형 알레르기 관리 계획을 한국어로 받아볼** 수 있다.

5. **사용자로서** 각 처리 단계를 **실시간으로 확인하고 필요시 수정**할 수 있다.

## 4. Functional Requirements

### 4.1 이미지 업로드 및 OCR 처리
1. 시스템은 JPG, PNG, PDF 형식의 알레르기 검사 결과 이미지를 업로드 받아야 한다.
2. 시스템은 OpenAI GPT Vision API를 사용하여 이미지에서 텍스트를 추출해야 한다.
3. 시스템은 SPT(피부단자검사)와 MAST(다중 알레르겐 검사) 두 가지 형식을 모두 인식해야 한다.
4. 시스템은 추출된 데이터를 OCR_prompt.md에 정의된 JSON 스키마 형식으로 구조화해야 한다.
5. 시스템은 OCR 결과를 사용자가 확인하고 수정할 수 있는 인터페이스를 제공해야 한다.

### 4.2 데이터 정규화 및 매핑
6. 시스템은 allergen_map_prompt_v2.json을 사용하여 알레르겐 명칭을 표준화해야 한다.
7. 시스템은 각 알레르겐에 대해 SNOMED CT 코드를 자동으로 매핑해야 한다.
8. 시스템은 검사 결과를 양성/음성으로 자동 판정해야 한다.

### 4.3 환자 정보 수집
9. 시스템은 환자의 이름, 나이, 성별을 입력받는 폼을 제공해야 한다.
10. 시스템은 입력된 환자 정보를 모든 생성 문서에 포함시켜야 한다.

### 4.4 FHIR Observation 생성
11. 시스템은 검사 결과를 HL7 FHIR Observation 리소스로 변환해야 한다.
12. 시스템은 각 알레르겐 검사 결과를 개별 Observation으로 생성해야 한다.
13. 시스템은 생성된 FHIR JSON을 미리보기하고 다운로드할 수 있게 해야 한다.

### 4.5 증상 피드백 챗봇
14. 시스템은 양성 알레르겐 목록을 대화형으로 제시해야 한다.
15. 시스템은 GPT API를 사용하여 한국어로 증상 경험을 수집해야 한다.
16. 시스템은 애매한 답변에 대해 재질문하여 명확한 분류를 유도해야 한다.
17. 시스템은 증상 피드백을 다음과 같이 분류해야 한다:
    - 증상이 있었던 알레르겐 (symptomatic)
    - 노출되었지만 증상이 없었던 알레르겐 (asymptomatic)
    - 노출 경험이 없는 알레르겐 (unknown_exposure)

### 4.6 FHIR AllergyIntolerance 생성
18. 시스템은 증상이 확인된 알레르겐만 AllergyIntolerance 리소스로 변환해야 한다.
19. 시스템은 allergyintolerance_builder.py 스키마를 준수해야 한다.
20. 시스템은 생성된 AllergyIntolerance JSON을 미리보기하고 다운로드할 수 있게 해야 한다.

### 4.7 맞춤형 리포트 생성
21. 시스템은 GPT API를 사용하여 한국어 알레르기 관리 리포트를 생성해야 한다.
22. 시스템은 다음 섹션을 포함한 리포트를 생성해야 한다:
    - 핵심 요약
    - 환경 관리 플랜
    - 의학적 관리 플랜
    - 생활습관 및 예방
    - 추적 관리 계획
    - 요약 결론
23. 시스템은 Markdown 형식의 리포트를 PDF로 자동 변환해야 한다.
24. 시스템은 환자의 이름, 나이, 성별을 리포트에 포함시켜야 한다.

### 4.8 사용자 인터페이스
25. 시스템은 Streamlit을 사용한 웹 기반 UI를 제공해야 한다.
26. 시스템은 처리 과정을 탭 또는 스텝퍼로 시각화해야 한다.
27. 시스템은 각 단계에서 사용자 확인(confirm) 후 다음 단계로 진행해야 한다.
28. 시스템은 각 단계별 결과물을 다운로드할 수 있게 해야 한다.
29. 시스템은 오류 발생 시 롤백 및 재시도 기능을 제공해야 한다.

### 4.9 데이터 저장 및 관리
30. 시스템은 처리 결과를 output 폴더에 자동 저장해야 한다.
31. 시스템은 파일명을 "환자이름_검사종류_YYYYMMDD" 형식으로 생성해야 한다.
32. 시스템은 처리 이력을 내부적으로 기록하고 관리해야 한다.

## 5. Non-Goals (Out of Scope)

1. 여러 환자의 데이터를 동시에 처리하는 일괄 처리 기능
2. 외부 EMR 시스템과의 실시간 연동
3. 환자 데이터의 암호화 및 보안 처리
4. 다국어 지원 (한국어와 영어만 지원)
5. 모바일 앱 개발
6. 약물 알레르기 검사 결과 처리
7. 검사 결과의 장기 추적 분석

## 6. Design Considerations

### UI/UX 설계
- Streamlit 기반 단일 페이지 애플리케이션
- 좌측 사이드바: 네비게이션 및 설정
- 메인 영역: 단계별 처리 화면
- 진행 상태 표시: Progress bar 및 Status indicator
- 다크/라이트 모드 지원

### 화면 구성
1. **Step 1: 이미지 업로드** - 드래그 앤 드롭 지원
2. **Step 2: OCR 결과 확인** - 편집 가능한 JSON 뷰어
3. **Step 3: 환자 정보 입력** - 폼 입력
4. **Step 4: 증상 피드백** - 채팅 인터페이스
5. **Step 5: FHIR 생성** - JSON 프리뷰 및 다운로드
6. **Step 6: 리포트 생성** - PDF 프리뷰 및 다운로드

## 7. Technical Considerations

### 기술 스택
- **Backend**: Python 3.8+
- **OCR Engine**: OpenAI GPT Vision API
- **LLM**: OpenAI GPT-4 API (GPT-5 when available)
- **Frontend**: Streamlit
- **FHIR**: HL7 FHIR R4 표준
- **PDF 생성**: ReportLab 또는 WeasyPrint

### 의존성 관리
- python-dotenv (환경 변수 관리)
- openai (GPT API 클라이언트)
- streamlit (웹 UI)
- Pillow (이미지 처리)
- pandas (데이터 처리)
- fhir.resources (FHIR 리소스 생성)
- reportlab/weasyprint (PDF 생성)

### API 통합
- OpenAI API 키는 .env 파일에서 관리
- API 호출 시 에러 핸들링 및 재시도 로직 구현
- Rate limiting 고려
