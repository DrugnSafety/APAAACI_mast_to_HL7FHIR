# 지역별 꽃가루 시기 + 초기 문진의 산출물 반영

## 1. LLM 소개문 검토 — 어디서, 어떻게

### 화면 (권장)

**http://127.0.0.1:8100/review**

| 버튼 | 동작 |
|---|---|
| 승인 | 그 문장이 즉시 환자 화면에 나가기 시작합니다 |
| 수정 후 승인 | 텍스트를 고친 뒤 승인 처리 |
| 문장 삭제 | 소개문만 지웁니다. 회피 수칙 등 템플릿은 그대로 남습니다 |

각 항목에는 판단에 필요한 맥락(시기·노출 환경·교차반응·생성 모델)이 함께 보입니다.
상단 탭으로 `검토 대기 / 승인됨 / 전체`를 전환합니다.

### 명령줄

```bash
python scripts/review_allergen_knowledge.py --list
python scripts/review_allergen_knowledge.py --show Walnut
python scripts/review_allergen_knowledge.py --approve Walnut Pecan
python scripts/review_allergen_knowledge.py --edit Bean --text "새 문장"
python scripts/review_allergen_knowledge.py --reject Latex
python scripts/review_allergen_knowledge.py --approve-all
```

### 검토 대상은 소개문뿐입니다

| 항목 | 출처 | 환자 노출 |
|---|---|---|
| 노출 환경 · 회피 수칙 · 교차반응 · 문진 프로브 | 사람이 쓴 카테고리·성분군 템플릿 | 검토 없이 **이미 노출** |
| 항원 소개문(`biology_ko`) | LLM 생성 | **승인 후에만** 노출 |

승인 전 상태는 API 응답에서 필드째 제거됩니다. 확인:
`GET /api/allergen?name=Walnut` → 승인 전에는 `biology_ko` 가 비어 있습니다.

## 2. 지역별 꽃가루 — 왜 필요한가

한국은 국토가 좁아 전국 하나로 충분합니다. 미국은 다릅니다.

| 지역 | 수목 꽃가루 시즌 |
|---|---|
| 남동부 (FL·GA·NC…) | **1~4월** |
| 남중부 (TX·OK) | **12~4월** — 한겨울 마운틴 시더 |
| 북동부·중부 대서양 | 3~5월 |
| 알래스카 | **4~6월** |

같은 "수목"이 지역에 따라 **석 달 넘게** 어긋납니다. 전국 평균으로 "봄에 조심하세요"라고 하면
텍사스 환자에게는 정점(12~2월)을 놓친 조언이 됩니다.

### 구현 (`services/pollen_forecast_service.py`)

두 층으로 답합니다.

**① 지역 달력** (`data/pollen_calendar_regional.json`, 키 불필요)
- 미국 10개 지역 — **50개 주 전부 매핑**(테스트로 강제)
- 중국 4개 지역 (화북·화동·화남·서북)
- 한국 1개 (전국) — 기존 종별 표(`pollen_season_korea.json`)를 그대로 씁니다

**② 실시간 예보** (선택, `GOOGLE_POLLEN_API_KEY`)
- [Google Pollen API](https://developers.google.com/maps/documentation/pollen/forecast) — 최대 5일,
  65개국, 1km 해상도, **월 5,000회 무료** 이후 $10/1,000회
- 응답의 식물 코드를 이 앱의 항원으로 매핑합니다:
  `RAGWEED→돼지풀`, `BIRCH→자작나무`, `ALDER→오리나무`, `MUGWORT→쑥`, `OLIVE→올리브`,
  `GRAMINALES→잔디`, `JUNIPER/CEDAR→삼나무`(측백나무과 — 마운틴 시더 포함)
- 키가 있고 위경도가 있으면 **실시간 값이 달력을 이깁니다**. 없거나 실패하면 조용히 달력으로 떨어집니다.

### 환자 결합

`for_patient()` 는 **이 환자가 양성인 꽃가루만** 골라 "지금 시즌인지"를 붙입니다.
진드기·음식은 제외되고, 거주 지역을 모르면 `available: False` 로 아무 말도 하지 않습니다 —
틀린 시기를 알려주느니 말하지 않는 편이 낫습니다.

### 입력

문진 3단계(탐험가 프로필)에 **거주 지역**(국가 → 지역/주)을 선택 항목으로 넣었습니다.
`ScreeningProfile.residence_country / residence_region / residence_lat / residence_lon`.
위경도는 선택이며, 있으면 실시간 예보에 씁니다.

### 실시간 예보를 켜려면

```bash
# .env
GOOGLE_POLLEN_API_KEY=...
```
`GET /api/pollen/regions` 의 `live_forecast` 로 켜졌는지 확인합니다.
위경도를 받으려면 화면에서 ZIP/주소 → 좌표 변환이 추가로 필요합니다(미구현).

## 3. 초기 문진이 리포트·카드뉴스에 반영되도록

### 고친 것

**카드뉴스는 `screening` 을 인자로 받기만 하고 어떤 카드에도 쓰지 않았습니다.** 동반 질환과
주증상을 물어놓고 산출물에 한 글자도 반영하지 않던 상태였습니다.

| 산출물 | 이전 | 지금 |
|---|---|---|
| 카드뉴스 | 문진 미반영 | **「처음 알려주신 정보」 카드** 신설 — 동반 질환별 문구, 주증상 부위, 항히스타민 SPT 주의 |
| 카드뉴스 치료 카드 | 질환 무시 | 천식·피부질환·아나필락시스 병력에 맞춘 줄 추가 |
| 카드뉴스 | 시기 정보 없음 | **「지금 조심할 꽃가루」 카드** (거주 지역이 있을 때만) |
| 리포트 | 주증상 부위를 나열만 | 부위별로 이번 판정과 **연결**해 설명 |
| 리포트 | 지역 개념 없음 | **거주 지역 기준 꽃가루 시기** 표 (지금 시즌 표시) |

### 하기도 증상 특례

주증상에 하기도(기침·천명·숨참)가 있는데 **천식 진단이 없으면** 리포트와 카드뉴스가
"이 검사로는 천식 여부를 알 수 없으니 진료에서 폐기능검사가 필요한지 확인하라"고 안내합니다.
진단하지 않고 확인을 권하기만 합니다. 이미 천식 진단이 있으면 이 문구는 나오지 않습니다.

### 실측 (텍사스 거주 · 천식 동반 · 하기도 증상)

리포트에 다음이 실제로 출력됩니다.

```
## 🗓️ 거주 지역 기준 꽃가루 시기 — 남중부 (텍사스·오클라호마)
**지금은 돼지풀 꽃가루 시즌입니다.**

| 알러젠 | 종류 | 시기 | 지금 |
| 자작나무 꽃가루 | 수목 | 겨울~봄 (12~4월) | ⚪ 비시즌 |
| 돼지풀 꽃가루 | 잡초 | 늦여름~늦가을 (8~11월) | 🔴 시즌 |

> 겨울에 정점을 찍는 '마운틴 시더(Mountain cedar, Juniperus ashei)' 시즌이 12~2월에 있습니다.
```

## 4. 남은 과제

- **지역 달력은 임상 검토 필요** (`review_status: curated_needs_clinical_review`). 월 단위 근사이며
  해마다 1~3주 차이가 납니다.
- **주소 → 좌표 변환 미구현**. 실시간 예보를 쓰려면 ZIP/도시 입력과 지오코딩이 필요합니다.
  지금은 위경도를 직접 넣어야 실시간 값이 쓰입니다.
- **중국 지역 구분이 거칩니다**(4개 권역). 쑥(Artemisia) 비중이 큰 북부 등 실제 문헌에 맞춰
  세분할 여지가 있습니다.
- 회피 수칙에 같은 취지 문장이 중복 출력되는 경우가 있습니다(Df·Dp 가 각각 수칙을 더함).
  상담 챗봇에는 중복 제거가 있지만 리포트에는 아직 없습니다.
