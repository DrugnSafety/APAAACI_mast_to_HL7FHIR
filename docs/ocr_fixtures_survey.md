# 검사 결과지 수집·합성 (OCR 픽스처)

OCR 은 이 플랫폼에서 LLM 이 반드시 필요한 유일한 구간인데, 손에 있는 실제 결과지가 5장뿐이라
회귀 검증이 불가능했다. 실제 결과지는 환자 식별정보를 담고 있어 모아 두기도 어렵다.
그래서 **실제 양식을 조사해 가짜 환자 정보로 합성 이미지를 만들고, 이미지마다 정답을 붙였다.**

| | |
|---|---|
| 생성기 | `scripts/generate_result_sheets.py` |
| 채점기 | `scripts/score_ocr.py` |
| 픽스처 | `tests/fixtures/ocr/` — 이미지 15장 + 정답 JSON 15개 + `manifest.json` |

---

## 1. 온라인 수집 결과

공개된 **샘플·안내용** 문서만 봤다. 실제 환자 결과지는 식별정보가 있어 수집하지 않았다.

| 출처 | 얻은 것 |
|---|---|
| [이랜드클리닉 MAST Allergy Test Report](https://www.elandclinic.com/Download/Documents/sample_MAST.pdf) | `SAMPLE` 워터마크가 찍히고 환자란이 비어 있는 **인쇄 검사보고서 실물 양식**. 머리말 3열 배치, `구분/Allergen명/한글/결과(IU/mL)/Class` 표, `<0.15` 표기, 혼합 항목의 병합 셀, 식품·흡입·아토피 패널 구성표 |
| [GC Labs MAST 안내문](https://www.gclabs.co.kr/BoardFiles/df85f49f-0371-4ab7-abfa-1f1c7b679650.pdf) | 검사 개요·판정 기준(class ≥ 2 를 양성으로 보는 관행) |
| [피부단자검사 판독 문헌](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC4763448/) | 팽진 3 mm 이상 또는 음성대조 대비 3 mm 초과를 양성으로 보는 기준, 히스타민 양성대조·생리식염수 음성대조의 역할 |
| [Pabau 피부반응검사 차트 템플릿](https://pabau.com/templates/allergy-skin-test-results-chart-template/) | 팽진·발적을 mm 로 따로 적고 대조를 함께 기록하는 서식 구성 |

**수집으로 확보할 수 있는 양은 여기까지였다.** 공개된 것은 대부분 마케팅 안내문이고,
검증에 쓸 만한 결과 표가 들어간 문서는 한 건뿐이었다. 그래서 합성으로 넘어갔다.

## 2. 저장소에 있던 실제 샘플 5장

`input_images/` 의 5장을 레이아웃 학습용으로 관찰했다. 이 파일들은 그대로 두고,
합성 샘플에는 **어떤 실제 환자 정보도 옮기지 않았다.**

| 파일 | 형태 |
|---|---|
| `mast_1.png` | EMR 터미널 텍스트 덤프. 어두운 배경, 고정폭, `NN. English(한글) : CL (값)` |
| `MAST_2.png` | 인쇄본을 휴대폰으로 촬영. 그림자·원근 왜곡·환자란 가림 처리 |
| `skin_prick_test_1.jpg` | EMR 피부단자 입력폼(라이트). 카테고리별 배경색, `Size` 열에 `4.5x3.5` |
| `skin_prick_test_2.jpg` | 같은 폼의 다크 테마 + 상단 툴바, 화면 캡처 |
| `그림1.png` | 참고용 |

## 3. 양식 5계열

조사와 관찰을 합쳐 서로 다른 5계열로 정리했다. OCR 이 어려워하는 지점이 계열마다 다르다.

| 키 | 형태 | OCR 난점 |
|---|---|---|
| `mast_lab_report` | 인쇄 검사보고서. 머리말 3열 + 2단 결과표, `구분/Allergen명/한글/결과/Class` | 한 행에 영문·한글·수치·class 가 붙어 있어 열 정렬이 흔들리면 값이 밀린다 |
| `mast_photo` | 같은 인쇄본을 촬영. `No/Allergen/Class/IU/mL` + 세로 구분열 | 그림자·원근 왜곡으로 오른쪽 열이 아래로 밀려 보인다 |
| `mast_emr_text` | EMR 터미널 텍스트. 어두운 배경, 2단 | 표 선이 없어 열 경계가 공백뿐이다 |
| `spt_form_light` | 피부단자 입력폼(라이트). 카테고리별 배경색 | `Size` 가 `4.5x3` 두 값이고, 빈칸이 "반응 없음"이다 |
| `spt_form_dark` | 같은 폼의 다크 테마 + 툴바 | 반전 대비, 툴바가 표로 오인될 수 있다 |

## 4. 합성 방법

```bash
python3 scripts/generate_result_sheets.py --out tests/fixtures/ocr --count 15
python3 scripts/generate_result_sheets.py --layout spt_form_dark --degrade photo --count 3
```

- **항원은 실제 레지스트리에서 뽑는다**(`data/allergens.json`). 카테고리 순서로 묶어
  실제 보고서처럼 그룹이 이어지게 배치한다.
- **환자 정보는 전부 가상이다.** 흔한 성 + 조합 이름, 가상의 병원명, 2026년 날짜를 쓴다.
  정답 JSON 에 `"synthetic": true` 를 박아 둔다.
- **결과 분포를 실제에 맞춘다.** 약 72%가 음성이고 그중 일부는 `<0.15` 로 인쇄된다.
  피부단자는 약 78%가 빈칸(반응 없음)이다.
- **학명만 약어로 쓴다.** 실제 결과지는 `Dermatophagoides farinae` 를 `D. farinae` 로
  인쇄하지만 `Russian thistle` 같은 영어 일반명은 줄이지 않는다. 접미사 규칙은
  `Aspergillus niger`·`Candida albicans` 같은 예외가 많아 속명을 명시적으로 나열한다.
- **글자수로 자르지 않는다.** 한글이 중간에서 깨지면 사람도 못 읽는 이미지가 되므로
  픽셀 폭을 재서 줄인다.

### 열화 단계

| 모드 | 처리 |
|---|---|
| `clean` | 원본 그대로. 스캔 PDF 수준 |
| `scan` | 미세 회전 + 약한 블러 + 종이 질감 + JPEG 압축 |
| `photo` | 원근 왜곡 + 그림자 그라데이션 + 조명 불균일 + 블러 + 강한 JPEG 압축 |

## 5. 정답과 채점

이미지마다 `<이름>.truth.json` 이 함께 나온다. 구조는 OCR 출력 스키마와 같아서 바로 비교된다.

```bash
python3 scripts/score_ocr.py --limit 5
```

항원 이름은 레지스트리 별칭으로 정규화해 맞춘다. 결과지에 `D. farinae` 로 인쇄되고
OCR 이 `Dermatophagoides farinae` 로 읽어도 같은 항원으로 센다.

| 지표 | 뜻 |
|---|---|
| recall | 정답 항원 중 몇 개를 찾았나 |
| precision | 찾은 항원 중 몇 개가 정답에 있나 |
| value | 수치가 맞나. `<0.15` 는 수치가 아니라 **미만 표기**로 맞아야 한다 |
| class | class 0–6 이 맞나 |
| size | 팽진 크기 원문(`4.5x3`)이 맞나 |

## 6. 픽스처가 찾아낸 결함 2건

만들자마자 실제 결함이 두 개 나왔다. 둘 다 **이미 배포한 기능이 OCR 에서 데이터를 못 받고
있던** 경우다.

### 6-1. `<0.15` 가 측정값 `0.15` 가 되고 있었다
FHIR 쪽에는 검출한계 미만을 `comparator "<"` 로 내보내는 처리가 있는데, 정작 OCR 프롬프트가
원문 문자열을 요구하지 않아 `<` 가 사라졌다. "0.15 미만"이 "측정값 0.15"가 되면 임상적 의미가
바뀐다. 프롬프트에 `value_text` 를 넣었더니 모델은 `value: null` 로 답하기 시작했지만 여전히
빈칸이었다. 파서가 **모델이 보낸 `value_text` 키를 무시**하고, `value` 필드가 숫자로 안 읽힐
때만 원문을 남기고 있었기 때문이다. 둘 다 고쳤다.

### 6-2. 피부단자 팽진 크기를 아예 못 읽고 있었다
프롬프트가 `SPT 는 팽진 크기를 value 에 mm 로` 라고만 해서 `4.5x3` 두 값 형식을 요구하지
않았다. 그 결과 `size_text` 가 늘 비었고, 장축·단축·평균·A/H 비를 담는
SPT `Observation.component` 가 통째로 비어 있었다.

### 개선 측정 (같은 픽스처 5장, gpt-4o)

| 지표 | 수정 전 | 수정 후 |
|---|---|---|
| 검사종류 | 5/5 | 5/5 |
| 재현율 | 100.0% | 99.4% |
| 정밀도 | 100.0% | 99.4% |
| 수치 | 64.5% | **77.6%** |
| class | 92.7% | 94.5% |
| 팽진 크기 | 77.7% | **99.0%** |

회귀 테스트 `test_ocr_preserves_below_detection_limit_and_wheal_size` 가 이 동작을 고정한다.

## 7. 남은 약점

- **촬영본의 수치 정확도가 48.6%로 가장 낮다.** 그림자와 원근 왜곡이 겹치면 오른쪽 열이
  밀려 보여 값이 이웃 행으로 섞인다. 전처리(기울기 보정·그림자 제거)를 넣을지, 프롬프트에
  행 정렬 규칙을 더할지 검토가 필요하다.
- 합성 샘플은 실제 인쇄·촬영의 모든 변형을 담지 못한다. 실제 결과지가 더 모이면
  `input_images/` 에 추가하고 같은 채점기로 함께 재면 된다.
- 지금 픽스처는 MAST·피부단자 2종뿐이다. UniCAP(ImmunoCAP) 양식은 아직 없다.
