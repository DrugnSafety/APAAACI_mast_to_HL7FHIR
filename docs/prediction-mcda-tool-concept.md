# [콘셉트] 약제별 기대효과 기반 맞춤 추천 도구 (MCDA) — 아이디에이션 정리

- 대상: pacen.myadr.care 치료 결정 지원 영역
- 성격: 아이디에이션 단계 콘셉트 문서 (구현 착수 전 운영위 논의용)
- 관련 근거: [계획서] "진료지침 기반 온라인 플랫폼 구축 계획안" (플로우차트·질의응답·MCDA 3개 모델),
  [설명서] I-6 MCID, I-7 환자 가치·선호도 조사, II-0 권고안 요약

## 0. 핵심 판단 요약

| 질문 | 판단 |
|---|---|
| 이론적으로 가능한가 | **가능.** [계획서]의 MCDA 모델("각 약제의 효과·안전성·비용·편의성을 점수화 후 가중치 반영", "가장 권장되는 약제 Top3와 예상 효과 점수화")과 동일한 구상이며, 필요한 데이터(메타분석 효과 크기, MCID, 선호도 축·가중치)가 과제 산출물로 이미 확보되어 있거나 확보 예정 |

## 1. 메뉴 배치 방안

### 권장안: 현행 대항목의 '허브화'

```
Decision Support (치료 결정 지원)          ← 현행 "Prediction & Response evaluation" 리네이밍
├─ Prediction — 약제 선택 지원
│   ├─ 적격성 필터 (표현형·생체표지자 기반)     [기존 flowchart 구상]
│   └─ 약제별 기대효과 + 선호도 반영 추천 (베타)  [본 문서의 MCDA 도구]
└─ Response Evaluation — 치료 반응 평가
    ├─ MCID·이상반응 허용 기준 (게시 원고)
    └─ 반응 평가 도구 (프로토타입 완료)
```

근거:

1. **성과지표와 1:1 대응** — [계획서] 고유성과 지표인 '진료지침 기반 온라인 플랫폼'의 실체가 이 대항목이 된다. 과제 보고 시 "홈페이지 내 Decision Support 섹션 = 온라인 플랫폼"으로 명확히 제시 가능.
2. **진료 시간축과 일치** — 치료 전 "어떤 약제를 시작할까?"(Prediction) → 치료 후 "반응이 충분한가?"(Response evaluation)의 대칭 구조가 실제 진료 흐름과 같다. 두 도구가 같은 대항목에 있어야 "선택 → 평가 → (KQ7 감량 / KQ8 교체)" 순환이 내비게이션으로 이어진다.
3. **콘텐츠와 도구의 분리 원칙** — 권고안·근거는 Key Questions(정적 콘텐츠), 도구는 Decision Support(인터랙티브)로 역할을 나누면 각 대항목의 정체성이 명확해진다. 챗봇은 자유 질의 인터페이스로 별도 유지하되 상호 링크.

### 대안 (도구가 커질 경우)

도구가 v2~v3(아래 로드맵)까지 성숙하면 "Online Platform"을 독립 대항목으로 분리하는 선택지도 있다.
다만 현시점에서는 메뉴 수를 늘리기보다 기존 대항목을 살리는 권장안이 적절하다. 기존 URL
(`/PredictionResponse/Prediction`, `/response-evaluation`)을 유지할 수 있다는 실무적 장점도 있다.

## 2. 제안된 도구의 파이프라인 설계 (5단계)

사용자 아이디어를 계산 가능한 단계로 분해하면 다음과 같다. 각 단계의 이론적 성립 여부를 함께 표기한다.

### 1단계 — 적격성 필터 (rule-based) ✅ 즉시 가능

- 입력: 혈중 호산구 수, FeNO, 총 IgE + 통년성 알레르겐 감작 여부, OCS 의존 여부, (연령·급여 조건)
- 처리: 권고문의 표현형 조건(알레르기성 / 호산구성 / 제2형 염증성)과 허가사항([설명서] 표1)을
  결정 규칙으로 변환 → **추천 가능 약제 후보군** 도출
- 이는 [계획서]의 '단계별 약제 선택 흐름도(flowchart)' 모델 그 자체다. 결정적(deterministic)
  규칙이므로 논란의 여지가 가장 적고, 도구의 신뢰 기반이 된다.

### 2단계 — 약제별 기대효과 표시 (evidence profile) ✅ 가능 (데이터 연결 필요)

- 각 KQ의 체계적 문헌고찰·메타분석에서 산출된 **약제별 outcome별 평균 효과 추정치와 95% 신뢰구간**을
  카드 형태로 표시 (예: 악화율비, OCS 감량, FEV1 변화량, ACQ 변화량)
- 필요 데이터는 이미 과제 내부에 존재(각 KQ 근거 프로파일). 도구는 이를 구조화된 표(약제 × outcome
  효과 매트릭스)로 옮기기만 하면 된다.

### 3단계 — 환자 기저치 결합 및 MCID 대조 ✅ 가능 (표준 EBM 방법)

- **상대효과의 절대화**: 상대 지표(예: 악화율비 0.5)는 환자의 기저치와 결합해야 개인 맥락의 절대
  기대효과가 된다. 기저 악화 4회/년 환자 → 기대 감소 2회/년, 기저 1회/년 환자 → 0.5회/년.
  이는 GRADE의 절대효과 산출과 동일한 표준 근거중심의학 기법으로, 방법론적으로 방어 가능하다.
- **MCID 대조**: 산출된 기대효과(점추정치·신뢰구간)를 델파이 합의 MCID와 비교해
  "평균 기대효과가 MCID 이상인가"를 배지로 표시.
- ⚠️ 표현 원칙: 이것은 "이 환자가 이만큼 좋아진다"는 개인 예측이 아니라 **"임상시험 근거상 이런
  특성의 환자군에서 기대되는 평균 효과"** 다. 도구 전반에서 '예측(prediction)'보다
  '근거 기반 기대효과(evidence-based expected benefit)'라는 표현을 권장한다.

### 4단계 — 후보 약제 간 비교 ⚠️ 조건부 가능 (핵심 방법론 쟁점)

- 한계: 각 약제의 효과 크기는 **위약 대비** 효과이며, 시험마다 대상 인구·설계가 다르다.
  약제 간 직접 비교(head-to-head) RCT가 없으므로 단순 수치 비교로 순위를 매기는 것은
  **간접 비교의 오류** 위험이 있다.
- 선택지:
  - **(a) 병렬 제시(권장 시작점)**: 순위 없이 적격 약제별 기대효과 카드를 나란히 표시하고,
    환자 특성과 표현형 조건의 부합 강도만 표기. 방법론적으로 가장 안전.
  - **(b) 네트워크 메타분석(NMA)**: 약제 간 비교 순위(SUCRA 등)를 정식으로 산출.
    별도 분석 작업이 필요하며, 산출 후에도 확실성 등급 명시 필요. 운영위·방법론 전문가 검토 사안.
  - 참고 근거: PACEN 1단계 실사용 연구에서 약제 간 악화 개선 효과는 유사했고, OCS 감량 효과는
    약제 간 차이가 있었다 — "outcome에 따라 약제 간 차이가 있을 수 있다"는 병렬 제시의 서사와 부합.

### 5단계 — 환자 선호도 가중 (MCDA) ✅ 가능 (조사 결과와 정확히 맞물림)

- 선호도 축은 **I-7 조사의 4개 축을 그대로** 사용: 천식 개선 효과 / 경제적 부담 / 약제 이상반응 / 사용 편의성
- 가중치 입력: 100점 배분 또는 순위 지정. **기본값은 I-7 조사의 환자 108명 평균**(효과 1.5위 >
  경제적 부담 2.37위 > 이상반응 2.6위 > 편의성 3.35위)으로 설정하고 개별 환자가 조정 —
  "환자 조사 결과가 도구의 기본값"이라는 서사는 과제의 환자 중심성을 그대로 보여준다.
- 항목별 점수화: 효과(3~4단계의 표준화된 기대효과), 이상반응(근거 프로파일의 AE), 비용(급여 적용
  여부·본인부담 수준), 편의성(투여 간격, 자가투여 가능 여부, 투여 경로) → 0~100 정규화 후 가중합
- 출력: 적격 후보군 내에서 "선호도 반영 우선 검토 후보" 제시. 가중치를 조정하면 순위가 바뀌는
  과정을 시각적으로 보여주는 것이 이 모델의 교육적 가치다([계획서]의 "가중치에 따라 우선순위가
  달라질 수 있도록 유연성 부여" 구현).

| 적격성 규칙 (표현형·허가·급여) | 권고문 조건 + 표1 + 급여 고시 | 규칙화 작업 필요 |

| (v3) 한국 실사용 검증 데이터 | KoSAR | 별도 연구 |

## 4. 반드시 도구에 명시할 한계 (표현 수위 가이드)

1. **평균 효과 ≠ 개인 예측** — 임상시험의 평균 치료효과이며 개인의 반응은 이질적이다.
2. **간접 비교의 한계** — 약제 간 비교는 head-to-head 근거가 아니므로 우열 단정 불가.
3. **상대효과 일정 가정** — 기저치 결합 절대효과는 상대효과가 기저 위험과 무관하게 일정하다는 가정에 기반.
4. **외적 타당도** — 임상시험 인구와 한국 실사용 인구의 차이. (향후 KoSAR 검증으로 보완 —
   [계획서]의 "플랫폼 축적 데이터로 향후 알고리즘 고도화" 항목과 연결되는 발전 경로)
5. **진료 판단 보조** — 최종 결정은 의료진과 환자의 공유 의사결정 사안이며, 급여 기준은 최신 고시 확인.

## 5. 규제·운영 검토 사항 (구현 전 확인)

- **의료기기 소프트웨어(SaMD) 해당 여부**: 개별 환자 데이터를 입력받아 특정 약제를 '추천'하는
  기능은 표현 방식에 따라 의료기기로 해석될 여지가 있다. "진료지침 권고안의 탐색·교육 도구"로
  설계·표현하고(치료를 지시하지 않음, 결과는 권고안 원문으로 연결), 필요시 식약처 가이드라인 검토.
- **개인정보**: 입력값을 저장하지 않는 클라이언트 측 계산 설계 권장. 저장·수집으로 확장할 경우
  IRB·개인정보 처리방침 필요.
- **책임 표현**: 모든 출력은 "조건부 권고" 틀 안에서 "우선 검토 후보"까지만. "최적 약제" 등
  단정 표현 금지.

## 6. 단계적 로드맵

| 버전 | 내용 | 성립 조건 |
|---|---|---|
| **v1** | 적격성 필터 + 적격 약제별 기대효과 카드 병렬 표시(CI 포함) + 환자 기저치 결합 절대효과 + MCID 충족 배지. **순위 없음** | 근거 프로파일 수치의 구조화만 필요 — 방법론 논쟁 최소 |
| **v2** | 선호도 가중 MCDA 추가 — 기본 가중치는 I-7 조사값, 사용자 조정 가능. 출력은 "선호도 반영 우선 검토 후보"(1~2개 그룹핑) | 항목별 점수화 방식(특히 비용)의 운영위 합의 |
| **v3** | NMA 기반 비교(순위 확률), KoSAR 실사용 데이터 검증, 축적 데이터 기반 고도화 | 별도 분석·연구 수행 |

Response evaluation 도구(완료된 프로토타입)와의 통합 시나리오: v2 이후 "치료 전 추천 →
치료 후 평가 → KQ7/KQ8 안내"를 하나의 환자 여정으로 연결하면 [계획서]의 온라인 플랫폼
구상이 완성된다.

## 7. 운영위 논의가 필요한 결정 사항

1. 약제 간 비교의 표현 수위: 병렬 제시(v1) vs 선호도 가중 우선순위(v2) vs NMA 순위(v3)
2. 효과 수치의 공식 출처 확정: 각 KQ 메타분석 최종값 vs 기존 발표 문헌 인용
3. 비용 축 점수화 방식: 급여 적용 여부만 반영 vs 본인부담 추정액 반영
4. SaMD 해당 여부 사전 검토 주체·시점
5. 도구 명칭: '추천'이라는 단어 사용 여부 (대안: "약제 선택 지원", "권고안 탐색기")
