# 10. HIS 연계와 데이터 보안 계획

병원 내부 처리와 검수 후 전달을 기본안으로 적용한다.

**버전 0.2 · 2026-10-29 · IRB 심의용 초안 · 미승인**

독자: 의료정보팀, 보안 담당자, 의료진, 연구진.
목적: 최소 데이터와 발송 통제의 인수 조건을 정한다.

## 1. 범위와 현재 상태

연구기관은 충북대학교병원 알레르기내과 검사실이다.
본 문서는 향후 병원 연계를 위한 협의 초안이다.
실제 HIS 큐와 알림톡 연계 완료를 뜻하지 않는다.
실제 환자정보를 처리할 운영 허가도 뜻하지 않는다.

기존 개발용 스캔 29건은 전향적 모집수에 넣지 않는다.
기존 파일의 연구 동의를 받았다고 가정하지 않는다.

HIS는 병원정보시스템을 뜻한다.
OCR은 스캔에서 문자와 값을 추출하는 처리이다.
FHIR은 의료정보 교환을 위한 HL7 표준 형식이다.
큐는 처리할 작업을 순서와 상태로 관리하는 목록이다.

기본안은 병원 내부 서버와 GPU를 사용한다.
의료정보센터가 GPU와 운영 권한을 관리한다.
연구진은 내부 qwen3.8 운영 구성을 제안한다.
정확한 모델 식별자와 배포 가능성은 확인하지 못했다.

DGX Spark에서 병원 GPU로의 이전은 향후 협의 사항이다.
병원 알림톡 서비스의 실제 연계 방식도 협의한다.
[기술 협조 요청서](../../medical_information_cooperation_2026-10-29/index.html)

환자정보의 외부 모델 API 전송은 기본안에서 제외한다.
국외 이전과 모델 학습 이용도 기본안에서 제외한다.
범위를 바꾸면 변경심의와 적법한 절차를 먼저 거친다.

## 2. 의료정보팀 협조 요청

의료정보팀은 다음 사항의 가능 여부를 검토한다.

1. 동의 상태를 조회할 안전한 접점을 정한다.
2. 적격 검사코드와 HIS 확정 상태를 정의한다.
3. 동의 후 확정 결과만 연구 큐로 연결한다.
4. 최소 필드의 읽기 전용 결과 경로를 제공한다.
5. 병원 내부 문진과 생성 서버를 배치한다.
6. 병원 GPU에서 승인한 모델을 운영한다.
7. 병원 알림톡 서비스의 발송 접점을 제공한다.
8. 접근권한, 로그, 백업과 사고 대응을 검증한다.

연구진은 HIS 전체 DB의 직접 접근을 요구하지 않는다.
연구 시스템은 HIS 진료 결과를 수정하지 않는다.
결과 조회 방식은 병원 허용 범위에서 정한다.
이벤트 연계와 주기 조회 중 방식은 확정하지 않았다.

서버 위치는 [의료정보팀 확정 후 기입]이다.
서버 책임자는 [운영 담당자 확정 후 기입]이다.
GPU 자원과 모델 배포 경로는 [확정 후 기입]이다.
진료 부서와 연구진은 검사 사건의 정의를 함께 확인한다.

## 3. 담당자와 권한

| 역할 | 허용 업무 | 통제 |
|---|---|---|
| 연구책임자 | 연구 운영과 승인 범위 관리 | 계정·역할 승인 |
| 동의 담당자 | 설명, 동의, 법정대리인 확인 | 동의 이력 보존 |
| 의료정보팀 | HIS 접점, 큐, 서버 운영 | 최소 운영 권한 |
| 발송 서비스 | 승인한 연락처와 메시지 전달 | 목적 외 이용 금지 |
| 생성 서비스 | 승인한 결과·문진으로 후보 생성 | 환자정보 외부 전송 차단 |
| 연구진 검토자 | 누락과 기술적 완결성 확인 | 임상 최종 승인 불가 |
| 임상 검수 의료진 | 값·해석·수신 자료의 최종 승인 | 지정 계정으로 승인 |
| 분석 담당자 | 연구번호 자료로 지표 산출 | 직접 연락처 접근 제한 |
| 보안 담당자 | 권한, 사고, 로그 점검 | 필요한 범위의 접근 |

공용 계정으로 검수 승인하지 않는다.
역할 변경과 퇴사 시 권한을 회수한다.
관리자 권한을 임상 승인 권한으로 간주하지 않는다.

## 4. 최소 필드와 분리 보관

| 구역 | 필요한 최소 필드 | 제외 또는 제한 |
|---|---|---|
| 동의 저장소 | 연구번호, 동의 버전·시각·상태 | 원본 서명 접근 제한 |
| 연결표 | 연구번호, 병원 환자 연결키 | 분석자료와 분리 |
| 수신자 저장소 | 검증한 전화번호, 관계, 권한 | 주민등록번호 미수집 |
| HIS 결과 | 사건키, 검사유형·항목·값·단위·기준치 | 전체 진료기록 미복제 |
| 결과 상태 | 확정시각, 정정 버전, 원천 식별자 | 중간 결과 사용 금지 |
| 문진 | 승인한 응답, 응답자 구분, 버전·시각 | 불필요한 자유문 입력 제한 |
| 사후 설문 | 연구번호·회차, 3종 응답자, 열람 분기, S1~S6·의견 | 새 식별정보 미수집 |
| 사후 일정 | 첫 확인 기록·선택·초대·만료·재알림·미발송 사유 | 임상 문진 일정과 분리 |
| 자료 저장소 | PDF·카드뉴스·FHIR, 파일 해시 | 공개 경로 배치 금지 |
| 검수 저장소 | 자료 버전, 검수자, 판정·사유·시각 | 수정 전 이력 보존 |
| 운영 로그 | 작업번호, 상태, 재시도, 오류코드 | 검사값·원문·원시 토큰 제외 |
| 분석자료 | 연구번호, 분모·분자·오류 분류 | 연락처와 병원 환자키 제외 |

연구번호를 써도 연결 가능한 자료는 익명 자료가 아니다.
운영자는 업무에 필요한 구역만 조회한다.
로그의 작업번호도 연결 가능성을 고려해 보호한다.

## 5. 데이터 흐름과 신뢰 경계

| 단계 | 출발 → 도착 | 허용 데이터와 통제 |
|---|---|---|
| 동의 | 설명 담당자 → 동의 저장소 | 동의·대리 권한·철회 상태 |
| 결과 | HIS → 병원 큐 | 유효 동의가 있는 적격 확정 결과 |
| 설문 발송 | 병원 → 병원 발송 서비스 | 확인한 연락처, 고정 안내문, 접근 URL |
| 응답 | 본인·보호자 → 병원 서버 | 인증 후 승인 설문 응답 |
| 생성 | 병원 서버 → 내부 모델·생성기 | 필요한 결과와 문진만 |
| 검수 | 병원 자료 저장소 → 지정 검수자 | 접근권한과 버전 확인 |
| 전달 | 병원 → 발송 서비스 → 수신자 | 승인 자료의 인증 URL |
| 자료 열람 | 인증 수신자 → 병원 저장소 | 승인 PDF·카드뉴스·선택 FHIR |
| 사후 초대 | 병원 → 확인한 수신자 | 선택 동의·일정 재검증 후 설문 URL |
| 사후 응답 | 인증 수신자 → 병원 설문 저장소 | 연구번호·회차로 가명 연결 |

병원 밖 발송업체가 처리하는 실제 항목을 기록한다.
외부 메시지 경계로 원천 검사 이미지가 넘어가지 않는다.
직접 PDF 첨부를 택하면 별도 경계 평가가 필요하다.
이 경우 업체가 처리할 PDF 내용도 명시한다.

## 6. 상태와 전이 조건

동의 유효 → queued → sent → response → generated → review → approved → delivered

| 상태 | 전이 조건 | 실패 시 처리 |
|---|---|---|
| queued | 유효 동의·적격 확정 결과·수신 권한 확인 | 보류와 원인 기록 |
| sent | 발송 시도와 업체 응답 기록 | 재시도 판단 또는 결과 조회 |
| response | 유효한 인증과 문진 접수 | 미응답·불완전 응답 구분 |
| generated | 원천 버전에 연결한 후보 생성 | 오류 상태와 검토 대기 |
| review | 연구진 확인과 의료진 임상 검수 | 반려 또는 수정 |
| approved | 지정 의료진이 해당 버전을 승인 | 임상 승인 전 발송 금지 |
| delivered | 확인한 수신자가 인증 후 자료 접근 | 전송 실패·미열람 구분 |

중간 결과와 생성 후보를 환자에게 자동 공개하지 않는다.
발송업체 접수를 delivered로 바꾸지 않는다.
등록, 실패, 철회와 만료 상태도 따로 기록한다.

사후 설문 상태는 임상 문진 상태와 별도로 관리한다.
선택 동의 → 예약 → 초대 → 응답 또는 만료로 기록한다.
미발송·거절·미열람·철회·정정 보류도 구분한다.
사후 설문 완료를 일차 전달 성공 조건으로 쓰지 않는다.
알림톡 전달 영수증만으로 수령과 읽음을 단정하지 않는다.
실패 상태를 지우고 성공 상태로 덮어쓰지 않는다.

## 7. 큐의 중복과 동의 변경

큐의 기본키는 연구번호와 검사 사건을 연결한다.
같은 결과 버전의 중복 이벤트는 작업 1건으로 합친다.
원천 버전과 작업 상태를 함께 확인한다.
발송 종류와 자료 버전별 중복 방지키도 사용한다.

시스템은 모든 실제 발송 전에 다음 항목을 재확인한다.

1. 동의가 현재 유효한지 확인한다.
2. 철회와 발송 금지 상태를 확인한다.
3. 수신자와 법정대리인 권한을 확인한다.
4. 원천 결과와 승인 자료의 버전을 확인한다.
5. 자료의 해시와 승인 상태를 확인한다.
6. 발송 기한과 중복 방지키를 확인한다.

동의 변경과 발송 준비는 잠금 또는 버전으로 제어한다.
철회 처리와 발송 준비가 겹치면 발송을 보류한다.
실제 외부 전송 직전에도 최신 상태를 확인한다.
외부 전송 자체와 내부 DB를 완전 원자적으로 묶기 어렵다.
기관은 이 잔여 경합 위험을 시험하고 기록한다.

철회 접수 후 대기 발송과 재알림을 취소한다.
이미 업체에 넘긴 요청은 취소 가능 여부를 조회한다.
취소할 수 없으면 접근 URL을 즉시 폐기한다.
이미 내려받은 파일은 원격 회수할 수 없다.

업체 응답이 불명확하면 결과를 조회한다.
결과를 확인하기 전에는 같은 알림을 무조건 재발송하지 않는다.
업체가 지원하는 중복 방지 기능을 확인한다.
지원하지 않으면 그 한계와 수동 복구 절차를 기록한다.

결과 정정은 새 버전을 만들고 기존 승인을 무효화한다.
같은 검사 사건의 정정을 새 대상자로 세지 않는다.
수정 자료는 의료진의 검수를 다시 거친다.
정정 중에는 사후 초대 예약도 보류한다.
같은 연구번호와 등록 회차의 사후 초대키는 1개이다.
이미 초대한 회차에는 자동 추가 초대를 보내지 않는다.

## 8. 본인과 보호자 수신 확인

동의 담당자는 환자와 검사 연결을 기관 절차로 확인한다.
전화번호만으로 환자 연결을 확정하지 않는다.
보호자 수신에는 법정대리인 자격과 관계를 확인한다.
동행자와 법정대리인을 구분한다.
연락처가 바뀌면 확인 전 발송을 보류한다.

보호자 권한 변경은 수신자 버전을 새로 만든다.
기존 보호자의 토큰과 접근권한은 폐기한다.
새 수신자는 기관이 정한 절차로 다시 확인한다.
법정대리인 확인 방식은 IRB와 병원이 확정한다.

URL 토큰은 추측하기 어려운 임의값을 사용한다.
기관은 원시 토큰 대신 검증용 해시 보관을 검토한다.
QR과 URL에 환자번호·성명·검사값을 넣지 않는다.
URL을 안다는 이유만으로 자료 열람을 허용하지 않는다.
기관은 별도 인증 방식과 세션 만료를 확정한다.

URL 유효기간 최대 30일은 **작성자 제안(PROPOSED)**이다.
철회·권한 변경·오류 발견 시 만료 전에도 폐기한다.
자료 열람 기한과 30일 일차 평가 기한은 구분한다.
만료 후 재발급은 동의와 수신 권한을 다시 확인한다.
재발급으로 일차 평가의 기한을 연장하지 않는다.

## 9. 문진의 수신과 검증

병원 서버는 인증한 본인 또는 보호자의 응답을 받는다.
응답에는 설문 버전과 응답자 구분을 저장한다.
본인 응답과 보호자 대리 응답을 구분한다.
같은 문진의 수정 이력과 최종 제출시각을 기록한다.

문항값은 승인한 형식과 허용 범위로 검증한다.
누락, 미확인, 모름과 아니오를 구분한다.
공란을 증상 없음으로 바꾸지 않는다.
응답 전송 실패를 문진 완료로 처리하지 않는다.
문진 수정 후에는 생성 자료의 갱신 필요성을 확인한다.
문진 변경으로 자료가 바뀌면 재검수를 시행한다.

### 사후 만족도 설문의 수신

사후 설문은 APAAACI-SAT-01 버전 0.1을 사용한다.
약 2분은 설계 목표이며 예비 조사로 확인한다.
내용은 6문항과 선택 의견 300자이다.
응답자는 본인·입력 도움을 받은 본인·보호자로 구분한다.
열람 자료는 보고서·카드뉴스·둘 다·미열람으로 구분한다.

미열람자는 점수 문항을 건너뛰고 이유를 선택한다.
평가 어려움·응답하지 않음·공란을 0점으로 바꾸지 않는다.
의견에 이름·연락처·자세한 건강정보를 쓰지 않게 안내한다.
사후 설문은 익명이 아닌 가명 연결 자료이다.
사후 응답과 자유 의견은 외부 AI와 언어모델로 보내지 않는다.
사후 설문을 거절해도 진료와 자료 전달에 불이익이 없다.

## 10. HIS와 OCR 대조

구조화한 HIS 결과를 우선 사용한다.
원천 검사코드와 표시명 사이의 매핑을 관리한다.
단위, 기준치, 등급과 결과 상태를 함께 받는다.
SPT의 측정값과 대조군 값을 구분한다.
검사유형별 원천 의미를 같은 점수로 강제 변환하지 않는다.

OCR은 승인한 보완 경로에만 사용한다.
지정 담당자는 원본의 모든 결과 행을 대조한다.
판독 불가 값과 잘린 행은 보류한다.
미확인 값을 0이나 음성으로 채우지 않는다.
원본과 추출값의 연결, 해시와 수정 이력을 보관한다.
필요한 재검토가 끝나기 전에는 자료를 승인하지 않는다.

## 11. 생성과 검수 승인

생성기는 입력·모델·설문·템플릿 버전을 기록한다.
생성기는 원천 결과와 문진의 해시를 기록한다.
생성 자료는 검수 전 후보 상태로 보관한다.
출력 형식 검증은 임상 검수를 대체하지 않는다.

연구진은 필드 누락과 파일의 완결성을 확인한다.
의료진은 값, 해석과 환자 설명을 최종 확인한다.
임상 승인 권한은 지정 의료진에게만 부여한다.
승인은 자료 버전과 파일 해시에 연결한다.

재생성과 수동 수정은 기존 승인을 무효화한다.
의료진은 최종 파일을 다시 확인한다.
발송기는 승인한 해시와 실제 파일 해시를 대조한다.
불일치하면 발송을 중단한다.
FHIR 검증은 구조·참조·코드를 확인한다.
FHIR 검증 통과를 진단의 정확성으로 표시하지 않는다.

## 12. 알림톡과 자료 제공

알림톡은 병원의 승인한 서비스를 이용한다.
개인 카카오 계정으로 대신 발송하지 않는다.
본문에는 고정 안내문과 접근 방법만 넣는다.
본문에 성명·검사값·진단명·주민번호를 넣지 않는다.
기관은 발신 채널과 안내문 문구를 승인한다.

기본 PDF 제공 방식은 인증 후 다운로드 URL이다.
카드뉴스도 인증 URL에서 확인한다.
FHIR은 본인 또는 보호자가 원할 때만 제공한다.
FHIR 수령을 원하지 않으면 자동 전송하지 않는다.

직접 PDF 첨부는 조건부 선택 사항이다.
플랫폼 지원과 기관 보안 검토를 먼저 확인한다.
업체가 처리할 PDF 정보와 보관 범위도 먼저 확정한다.
필요한 설명과 동의에 실제 처리 내용을 반영한다.
이 조건을 충족하기 전에는 직접 첨부하지 않는다.

사후 설문만 중단하면 임상 자료 전달은 유지한다.
임상 문진 완료·철회·권한 상실 후에는 그 재알림을 중단한다.

백업의 순환 삭제와 복원 시 차단 절차도 적용한다.
기관은 대상, 시점과 파기 결과를 기록한다.
