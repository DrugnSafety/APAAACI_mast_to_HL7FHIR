# 문진·리포트 생성 규칙 (Questionnaire & Report Generation Rules)

> 목적: 문진 흐름과 리포트 서술을 **하드코딩이 아닌 규칙(rule)** 으로 명세한다. 규칙은
> 데이터(레지스트리·성분 엔진)와 결합해 결정론적으로 문진·리포트를 생성한다.
> (superpowers/gsd 플러그인을 이 실행환경에서 못 써서, 동일 방법론으로 규칙을 문서화한다.)

핵심 임상 원칙: **검사 양성 = 감작**일 뿐, 임상 알레르기는 **노출 시 재현 증상**으로 확정.
성분 공유는 **교차반응 후보**만 만들고, 실제 반응은 **증상**으로 확정한다(CRD).

---

## A. 문진 규칙 (Questionnaire Rules)

### Q-1. 모든 양성 항원은 반드시 최소 1개의 노출·증상 질문을 받는다(누락 원천 차단)
- 카테고리별 전용 질문: pollen(시즌), mite/insect/mold(실내 노출), animal(접촉·악화), food(섭취 증상).
- **`other`/미분류 양성 항원도 예외 없이** 범용 "노출·섭취 시 증상" 질문을 받는다.
  (예: 레지스트리에 없는 `Mushroom`(버섯)이 `other`로 떨어져도 질문 누락 금지.)
- 데이터 보강: 명백한 음식(버섯 등)은 base map 에 추가해 `food` 로 정분류(add-to-list).

### Q-2. 동물(실내 사육 가능) 항원: 양성이면 전부 노출·증상 질문
- 각 양성 동물마다 `접촉 여부` + `접촉 시 증상 악화` 질문.
- 판정: `악화=예` → 임상 유의(사육 여부 무관 — "안 키우지만 노출 시 증상" 포함).
  `접촉=예 & 악화=아니오` → 감작만. `접촉=아니오` → 미확정(관찰).

### Q-3. 교차반응 질문은 "원인 항원이 증상 있음/불명"일 때만 proactive
- 근거: 감작만 되고 **명확히 무증상**인 항원의 교차반응을 묻는 것은 임상적 의미가 낮다.
- 게이트(reveal): 항원 X 의 교차반응 음식 질문은 **X 의 증상 질문이 `예` 또는 `잘 모르겠어요`** 일 때만 노출.
  - pollen X → `pollen_season[group] ∈ {yes, unsure}`
  - mite/insect/mold → 해당 실내 노출 질문 ∈ {yes, unsure}
  - animal X → `animal_worse[X] ∈ {yes, unsure}`
  - food X → `food_symptoms[X]` 에 증상 포함 또는 `shellfish_react[X] ∈ {oral, systemic}`
- **명확히 무증상**(no)이면 그 항원의 교차반응 질문은 숨긴다.

### Q-4. 음식 문진은 마지막에 통합(consolidation) + 교차반응 우선
환경/꽃가루 섹션에서는 **노출·증상만** 묻고, 음식 관련 질문은 마지막 음식 섹션에 모은다.
음식 섹션 순서:
1. **직접 양성 음식** — 각 양성 food 항원의 섭취 증상(항상 질문).
2. **교차반응(항원별 그룹)** — Q-3 게이트로 증상 있는 항원만 proactive. 원인 항원별로
   "○○ 감작으로 아래 음식 교차반응 가능 — 드셨을 때 증상?" 형태.
3. **종합 음식반응 catch-all(재활성 트리거)** — "지금까지 안 여쭤본 음식 중 드셨을 때
   이상반응 있던 것 모두" (옵션 = 교차반응 후보 음식 통합). 여기서 특정 음식을 지목하면,
   그 음식의 **원인 항원 교차반응 질문이 (무증상이라 숨겨졌더라도) 재활성**된다.
   - 구현: 교차반응 질문의 reveal 조건에 `{종합질문 includes_any: 해당 항원 후보음식}` 을 OR 로 추가.
4. **전신 음식반응 게이트** — 안전망(패널에 없던 음식 포함).

### Q-5. 게이트/재활성은 프론트 reveal 로만 구현(정적 빌드 유지)
`reveal_if_any = [ {X증상 any:[yes,unsure]} , {종합질문 includes_any:[후보음식…]} ]` (OR).
`condMet` 이 `any_of` 를 재귀 평가하고 답변 변경 시 동적 재평가하므로 게이트+재활성이 한 조건에 담긴다.

## B. 리포트 규칙 (Report Rules)

### R-1. '앞으로 주의해서 관찰할 음식'은 **원인 항원(카테고리)별로 그룹화**
- 개별 음식 나열 금지. 원인 항원별로 묶는다:
  - "「고양이 비듬」과 교차반응 가능: 소고기·돼지고기…"
  - "「오리나무 꽃가루」과 교차반응 가능: 사과·복숭아·헤이즐넛…"
- confirmed(증상 보고) 는 별도 강조, risk(가능성만) 는 관찰 대상으로 구분.
- 가능성만 있는 성분을 과도하게 구체적으로 단정하지 않는다(관찰 프레이밍).

### R-2. **OAS/교차반응 확대 가능성 경고**(최우선 서술)
- 현재 반응 음식이 일부(예: 체리·자두·살구)라도, **같은 성분(component)을 공유하는
  다른 음식으로 시간이 지나며 교차반응이 확대**될 수 있음을 명시.
- 프레이밍(예): "지금은 체리·자두·살구에 반응하지만, 이들과 같은 계열(PR-10 등)의
  다른 과일·채소에서도 향후 입·목 증상이 새로 생길 수 있으니, 새 음식 섭취 시 관찰하세요."
- 데이터 근거: 원인 항원이 공유하는 성분 family 로부터 "같은 계열 음식군"을 제시.

### R-3. confirmed(증상 확인) 교차반응은 리포트·카드뉴스에 반영, risk 는 관찰 안내
- confirmed → 별도 관리 대상(주의). risk → "가능성, 관찰" 수준으로만.

## C. 데이터 연결(구조화)
- 교차반응 후보/성분 계열: `services/crossreactivity_service.py` (레지스트리+성분 엔진).
- 카테고리: `services/category_resolver.py` (미분류→other 로그 = add-to-list 후보).
- 규칙 변경은 코드가 아니라 데이터(base map·membership·category_rules)에 추가하는 것을 우선.
