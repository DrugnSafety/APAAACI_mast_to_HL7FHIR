# 실손 모듈·비급여 처리·사이트맵 개정 (9차)

## 1. 반영된 결정 사항

| 결정 | 구현 |
|---|---|
| Reslizumab 4 mg/kg 기준 | ✅ 회당 4mg/kg → 100mg 바이알 **내림**(잔량 미발생) — 65kg: 260mg → 2바이알(200mg) 투여·799,104원/회. ⚠ 내림 방식이 처방 용량 미달을 낳는 구간이 있으므로(260→200mg) 실제 임상 반올림 관행 재확인 권장 |
| 비용 축 최저가: 적격군 내 | ✅ 기본 환자에서 순위 변동 발생 — reslizumab(첫해 실부담 최저)이 1순위로 상승. 기준 변경이 결과를 바꾸는 살아있는 예시 |
| 실손 모듈 적용 | ✅ 외래/입원 분기 구현 (아래 3절) |

## 2. 비급여 0점·OCS 결측 — "작업이 의미 없어지는 것 아닌가"에 대한 답

**아니다 — 이것은 방법론의 결함이 아니라 데이터 상태의 정직한 반영이며, 셋 다 해결 경로가 있고 두 개는 이번에 구현했다.**

### 2-1. 비급여(테즈파이어) — 0점을 버리고 두 갈래로 해결 (✅ 구현)

- **해결 A (구현)**: 비용 축의 기준을 '표시가'에서 **'환자 실부담'**으로 바꿨다. 비급여의 본질은 "가격 정보가 없음"이 아니라 "전액 본인부담"이므로, **비급여 예상가 입력 필드**(병원 고지가)를 받으면 전액 본인부담으로 같은 공식에 들어간다 — 0점 문제 소멸, 연속 점수 획득.
- **해결 B (구현)**: 예상가 미입력 시에는 0점이 아니라 **비용 축 제외 + 남은 축 재정규화**로 처리한다(효과 축의 '근거 없음' 처리와 동일 원칙). 카드와 계산 상세에 사유가 명시된다.
- 그리고 이것은 시간이 해소하는 문제다: 테즈파이어가 급여 등재되면 상한가 한 줄만 갈아끼우면 된다. **방법론 문제가 아니라 데이터 갱신 문제**다.

### 2-2. OCS 지표 결측 — 결측의 종류별로 이미 규칙이 있다

- reslizumab OCS(근거 없음 — OCS-sparing 시험 부재): 축 제외·재정규화 ✅
- tezepelumab OCS(전용 시험에서 유의차 없음): 0점이 정당(효과 없음의 근거) — 카드에 사유 표시 ✅
- **근본 해결 경로**: KQ6 부록에 SOURCE 시험의 OCS 감량률(%) 데이터가 있다면 다른 약제와 동일 지표로 재추출 가능 — 근거팀 확인 요청 사항. 이 경우 tezepelumab도 연속 점수를 받는다.

### 2-3. 왜 작업이 여전히 의미 있는가

MCDA의 가치는 '모든 칸이 찬 완벽한 표'가 아니라 **결측·불확실성을 명시한 투명한 비교**다. 지금 도구는 ① 모든 결측의 사유와 처리 규칙을 화면에 노출하고, ② 처리 방식이 결과를 바꾸는지 토글로 확인 가능하며, ③ 결측은 데이터가 도착하는 대로(급여 등재, 원자료 추출) 좁혀진다. 오히려 결측을 숨긴 채 매끈한 순위만 내는 도구가 의미 없는 쪽이다.

## 3. 실손보험 모듈 — 외래/입원 분기 (✅ 구현)

### 입원 투여 + 실손

지적 그대로 반영: **비용 축 자동 제외**(남은 축 재정규화) + 고지. 실손 입원의료비가 대부분을 보장하므로 약제 간 비용 차이가 환자 부담 차이로 이어지지 않는다는 판단을 그대로 구현했다. 단 세 가지 확인 문구를 유지한다: 입원 적정성(심사 삭감 리스크), 세대별 입원 보장률(80~100%), 비급여 주사 특약 여부.

### 외래 투여 + 실손

보험마다 다른 인정 기준은 **증권 파라미터 3개 입력**으로 반영한다(세대 자동 판정은 하지 않음 — 세대·특약별 편차가 커서 잘못된 기본값이 더 위험):

```
회당 실부담 = 본인부담금 − min( max(본인부담금 − max(정액공제, 본인부담금×자기부담률), 0), 회당 보장한도 )

입력: 정액공제(원/회) · 자기부담률(%) · 회당 보장한도(원)   — 본인 증권 기준
```

회당 한도 구조 때문에 **투여 횟수가 많은 약제(두필 26회/년)가 한도를 더 많이 활용**해 실손 후 순위가 뒤집힐 수 있다 — 이 비자명한 결과를 보여주는 것이 모듈의 실질 가치다. 향후 운영위가 세대별 대표값을 확정하면 프리셋 버튼(1~2세대/3세대/4세대) 추가 가능. 4세대의 급여/비급여 분리 보장은 v2 정교화 항목.

## 4. 사이트맵 개정 — 대항목은 유지, 세부항목 4건 변동

초기 제안(1차) 대비 대항목 7개 골격은 그대로 유효하다. 그간 결정·구현으로 세부항목이 다음과 같이 진화한다:

```
3. Decision Support (치료 결정 지원)        ← 명칭 확정 (구 Prediction & Response evaluation)
   ├─ 약제 선택 지원 (Prediction)            ← 데모 실물화: 적격성 필터·병렬 카드·MCDA
   ├─ 치료 반응 평가 (Response Evaluation)   ← MCID 도구 (기존 확정 유지)
   ├─ ★ 비용·보험 계산기                     ← 신설 분리: 약가·용량표·실손 모듈이 커져 독립 페이지 가치.
   │                                          약제 선택 지원과 상호 연동(적격 약제의 비용 상세)
   └─ ★ 약제 간 비교 참고치 (NMA · 예정)      ← 공통 하위군 부합 환자 한정 모듈 — NMA 수행 후
5. For Patients (환자 마당)
   └─ '나에게 맞는 치료 알아보기'              ← 도구의 '환자 보기' 모드와 직접 연결 (신설 아닌 구체화)
6. Resources (자료실)
   └─ ★ NMA 방법론 자료                      ← 추가 예정 (출판 시 프로토콜·데이터셋 공개)
7. 개정·갱신 정책
   └─ ★ 데이터 기준일 관리                    ← 신설: 약가·급여 상태·용량표는 지침(3~5년)과 달리
                                              수시 고시로 변동 — 기준일·갱신 이력을 별도 관리
```

나머지 대항목(Introduction, Key Questions, Chatbot)과 그 하위 구성은 1차 제안 그대로 유효하다. 요약: **대항목 변동 없음, 세부항목 신설 3건(비용·보험 계산기, NMA 방법론 자료, 데이터 기준일 관리) + 구체화 2건(NMA 비교 모듈 예정, 환자 마당-환자 보기 연결)**.

## 남은 확인 사항 (갱신)

1. Reslizumab 바이알 내림 방식의 임상 타당성 (260mg 처방 → 200mg 투여 구간)
2. KQ6 부록의 SOURCE OCS 감량률(%) 데이터 존재 여부 → tezepelumab OCS 지표 동일화
3. 테즈파이어 비급여 예상가 대표값 (병원 고지가 조사)
4. 실손 세대별 프리셋 대표값 (운영위·보험 실무 확인)
5. 투여 행위료·진찰료 포함 여부 (현재 약제비만)
