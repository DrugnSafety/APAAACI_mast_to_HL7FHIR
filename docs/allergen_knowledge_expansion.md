# 항원 일반 정보 확충 (148종)

## 1. 왜 했나 — 확인된 격차

레지스트리에는 항원 **148종**이 있는데 사람이 쓴 개별 지식은 **18종**뿐이었습니다.
나머지 **128종은 지식이 0개**로, 도감 카드의 `노출 환경`·`회피 수칙`·`교차반응`이 전부 비어 있고
설명은 "상세 정보는 준비 중입니다"로 나갔습니다.

수집 방식을 정하려고 위키백과를 실측했으나 **부적합**했습니다.

> 미보유 항원 40종 표본 중 문서 존재 **38%**. 있어도 알레르기와 무관합니다 — "바나나" 61자,
> "호두" 78자짜리 과일 설명. `삼나무`·`미국바퀴`·`말 비듬`·`고등어`는 문서 자체가 없습니다.

환자에게 필요한 필드(노출 환경·국내 시즌·회피 수칙·교차반응)는 백과사전 도입부에서 나오지 않습니다.

## 2. 무엇을 넣었나 — 두 갈래

| | 방식 | 환자 노출 | 대상 |
|---|---|---|---|
| **A** | 카테고리·성분군 템플릿 + 국내 꽃가루 시기 | **즉시** | 128종 전부 |
| **B** | LLM 항원 소개문 | **검토 후에만** | 126종(대조 2종 제외) |

A 는 결정론적이고 사람이 쓴 문장이라 바로 내보냅니다. B 는 `candidate` 로 저장되고
`KnowledgeService` 가 기본적으로 걷어내므로 승인 전에는 화면에 나오지 않습니다.

### A. 템플릿 (`data/allergen_category_profiles.json`)

회피 수칙·노출 환경·문진 프로브는 실제로 카테고리 단위로 같습니다(진드기 2종, 곰팡이 9종은 같은 조언).
**음식만은 이름이 아니라 성분군으로 묶습니다** — 교차반응과 위험도가 성분을 따라가기 때문입니다.
레지스트리에 이미 붙어 있던 성분 태그를 그대로 씁니다.

| 성분 | 템플릿 | 종수 | 임상 요점 |
|---|---|---:|---|
| `nsltp` | `food:ltp` | 15 | 열·소화에 강함 → 익혀도 남고 전신반응 가능 |
| `tropomyosin` | `food:shellfish` | 12 | 갑각·연체 교차, 진드기·바퀴와도 교차 |
| `parvalbumin` | `food:fish` | 8 | 어종 간 교차, 조리 증기도 노출 |
| `2s_albumin` | `food:seed_storage` | 6 | 견과·씨앗, 가열로 줄지 않음 |
| `pr10` | `food:pr10` | 5 | 자작나무 관련 OAS, 익히면 완화 |
| `profilin` | `food:profilin` | 4 | 범알레르겐, 다수 양성이나 증상 연결은 낮음 |
| `serum_albumin` | `food:mammal_meat` | 2 | pork-cat 증후군 등 |
| (성분 없음) | `food` | 23 | 일반 음식 |

나머지: `pollen_tree` 15 · `mold` 9 · `pollen_grass` 8 · `animal` 8 · `pollen_weed` 7 ·
`mite` 2 · `control` 2 · `insect` 1 · `other` 1.

대조 항목(생리식염수·히스타민)은 `is_control: true` 로 표시하고 **회피 수칙을 주지 않습니다** —
알레르겐이 아니라 검사가 유효한지 확인하는 대조이기 때문입니다.

### 국내 꽃가루 시기 (`data/pollen_season_korea.json`)

꽃가루 30종에 카테고리 기본값(수목 3~5월 등) 대신 종별 시기를 넣었습니다.
예: **삼나무 2~4월**(제주·남부는 1월 말 시작), 우산잔디 5~9월, 국화 9~10월.

교차반응도 **과(科) 단위**로 정확히 씁니다. 초안에서 삼나무(측백나무과)에 "자작나무과 PR-10"이
붙는 오류가 있었고, 종별 문구로 교정했습니다. 충매화(민들레·국화·아까시)는 공기 중 농도가 낮다는
점을, 혼합 항원(나무 혼합·잔디 혼합)은 원인 종을 특정할 수 없다는 점을 명시합니다.

### B. LLM 소개문 (`--llm`)

항원이 "무엇이고 어디서 만나는지"만 1~2문장으로 씁니다. 회피 지시·유병률·검사 수치는 프롬프트에서
금지했고, 확신이 없으면 `UNKNOWN` 을 반환해 건너뜁니다.

생성 결과 126건, 평균 43자. 자동 점검에서 **조언·유병률 주장·환자 단정·검사 수치 언급 0건**.

## 3. 검토 절차

```bash
python scripts/review_allergen_knowledge.py --list              # 검토 대기 목록
python scripts/review_allergen_knowledge.py --show Walnut       # 한 건 상세
python scripts/review_allergen_knowledge.py --approve Walnut Pecan
python scripts/review_allergen_knowledge.py --edit Bean --text "새 문장"
python scripts/review_allergen_knowledge.py --reject Latex      # 문장 삭제(템플릿은 유지)
python scripts/review_allergen_knowledge.py --approve-all       # 전체 승인(검토 후에만)
```

승인 전까지 `biology_ko` 는 API 응답에서 제거됩니다. 템플릿 필드(회피 수칙 등)는 영향받지 않습니다.

**검토 시 눈여겨볼 예**: `콩(Bean)` 소개문이 "두유·두부·된장"을 들었는데 이는 대두(soybean)
설명에 가깝습니다. 레지스트리의 `Bean` 은 일반 콩이라 교정이 필요할 수 있습니다.

## 4. 조회 우선순위 — 그리고 고친 버그

```
1) 개별 지식 정확 일치 (사람이 쓴 18종)
2) 템플릿 지식 정확 일치 (128종)
3) 개별 지식 부분·퍼지 매칭 (레지스트리에 없는 OCR 변형 구제용)
4) 카테고리 기본값 + 위키 요약
```

2와 3의 순서가 중요합니다. 기존 코드는 퍼지 매칭이 먼저라 **엉뚱한 항원의 지식이 붙었습니다**:

| 항원 | 붙었던 지식 | 원인 |
|---|---|---|
| **굴 (Oyster)** | 환삼덩굴 꽃가루 — 음식에 가을 시즌·야외 회피 수칙 | "굴"이 "환삼덩굴"의 부분 문자열 |
| 콩 (Bean) | 땅콩 | "콩"이 "땅콩"의 부분 문자열 |
| 토끼·쥐 상피 | 고양이 비듬 | 퍼지 매칭 |
| 미국바퀴 | 독일바퀴 | 퍼지 매칭 |

정확 일치 템플릿을 퍼지보다 앞에 두어 해결했고, 회귀 테스트(`TestFuzzyMatchingDoesNotCrossCategories`)
를 붙였습니다.

## 5. 재생성

```bash
python scripts/build_allergen_knowledge.py            # 템플릿만 (LLM 문장·승인 이력 유지)
python scripts/build_allergen_knowledge.py --llm      # + 소개문 생성(없는 항목만)
python scripts/build_allergen_knowledge.py --dry-run  # 통계만
```

템플릿을 고친 뒤 재생성해도 기존 LLM 문장과 승인 상태는 그대로 옮겨옵니다(재과금 방지).
생성기의 이름 매칭은 `KnowledgeService._norm` 과 같은 정규화를 씁니다 — 달라지면 서비스는 개별 KB 로,
생성기는 템플릿으로 각각 다르게 판단해 중복이 생깁니다(실제로 9종에서 발생).

## 7. 남은 과제

- **꽃가루 시기는 임상 검토 필요**: `review_status: curated_needs_clinical_review`. 지역(중부/남부/제주)과
  해마다 1~3주 차이가 나며 월 단위 근사입니다.
- **음식 23종은 성분 태그가 없어** 일반 `food` 템플릿만 받습니다. 성분을 붙이면 교차반응이 정확해집니다.
- **개별 지식 확충**: 임상적으로 중요한 항원부터 18종 수준의 개별 문서를 늘리면 템플릿보다 정확합니다.
- LLM 소개문 126건은 **검토 대기 상태**입니다.
