## 1. 결과 검증 규칙 — `services/ocr_validation.py`

값을 고치지 않고 **표시만** 단다. 표시된 행은 확인 화면에서 강조된다.

- class ↔ 수치 불일치 (ImmunoCAP 경계 0.35/0.7/3.5/17.5/50/100)
- `<` 미만 표기인데 class ≥ 1
- 인쇄 문자열과 모델 숫자가 다름 — 프롬프트가 수치 칸을 **인쇄된 그대로**(`value_raw`) 받고, 파서가
  `.48` 을 직접 0.48 로 읽는다(모델이 4.8 로 옮긴 적이 있다)
- 수치·팽진 크기 범위 이탈, 팽진 크기 해석 실패
- 항원명을 목록에서 못 찾음, 같은 항원 중복
- 인쇄된 행 번호(`no`)가 비면 빠진 행 번호를 알림
- 환자명 옆 라벨(`name_label`)이 검사자·의사 칸이면 알림
- SPT 에서 히스타민 대조를 못 읽음

항원명 매핑도 보강했다: 괄호 없이 붙은 `Fusarium 붉은점박이곰팡이` 를 영문·한글로 나눠 찾고,
`Dog(개)`·`바퀴벌레 혼합` 별칭을 추가했다(인쇄보고서 한 장이 34/69 행만 매핑되던 원인).

## 2. 이미지 전처리 — `utils/image_preprocess.py`

Pillow + numpy 만 쓴다(OpenCV 없이).
- EXIF 회전 보정, 폭 1600px 미만이면 확대
- 촬영본(배경 밝기 편차가 큼)이면 조명 평탄화 — 크게 흐린 사본으로 나눠 그림자를 걷어낸다.
  색은 남긴다(영어 결과지의 색 막대, 중국어의 빨간 `+`)
- 좌우 2단 분할은 시도했다가 버렸다: 가운데 거터를 찾는 방법이 한 표 안의 빈 열을 거터로
  오인했다. 대신 양식을 가정하지 않는 **위·아래 절반 확대본**을 두 번째 판독에 쓴다.

## 3. 두 번 읽기 — `ocr_validation.merge_double_read`

첫 판독은 전체 이미지, 두 번째는 위·아래 절반 확대본(서로 다른 시점). 행마다 비교해
- 값이 다르면 표시하고 다른 판독값을 메모로 남긴다
- 두 번째에만 있는 행은 추가하고 표시한다(첫 판독이 빠뜨린 행 복구 — 촬영본 재현율 94.6→100%)
- 비용·시간은 약 2배. `OCR_DOUBLE_READ=false` 로 끌 수 있다.

- 처음엔 `gpt-5.5` 를 기본값으로 했고, 2026-09-24 사용자 결정으로 `gpt-5.6-luna` 로 바꿨다

- luna 는 위 비교(옛 프롬프트)에서 영어 결과지 검사종류를 2/3 틀렸지만, 새 프롬프트·전 과정에서는
  21/21 로 맞혔다. 대신 class 정확도 92.5%(gpt-5.5 100%), 맞는 행 확인 표시 6.7%(0.9%)로

- gpt-5.4-mini·luna 는 영어 결과지를 UniCAP 으로 분류하는 실수가 있었다.
- Gemini 는 키의 프로젝트가 분당 요청 한도 초과로 응답하지 않아 측정하지 못했다(호출 코드는 있음:
  `--model gemini-...`).

## 5. 전용 OCR 결합 — `utils/ocr_text_layer.py` (기본 꺼짐)

지금 쓸 수 있는 엔진은 로컬 Tesseract 뿐이다. 단독으로는 항원명을 뭉개고 **소수점을 잃는다**
(`0.23`→`023`). 그래서 모델에 "행 순서 확인용, 숫자는 이미지를 믿으라"고 못 박고 참고로만 붙인다.

gpt-4o, 촬영본·중국어 6장, 한 번 읽기:

| | 수치 | 양성 누락 | 10배 |
|---|---|---|---|
| 텍스트 층 없음 | 70.3% | 24/47 | 3 |
| 텍스트 층 있음 | 83.1% | 11/47 | 0 |

gpt-4o 에는 도움이 됐지만 gpt-5.5 는 이미 거의 오류가 없어 기본은 껐다(`OCR_TEXT_LAYER=true`).
상용 엔진(Google Document AI·Azure·Upstage)이 생기면 같은 자리에 엔진만 바꿔 끼우면 된다.

## 6. 확인 화면 필수화 — `web/app.js`, `web/classic/app.js`

- 검증 표시가 있으면 표 위에 경고 배너, "확인 필요" 탭, 행마다 이유와 다른 판독값을 보여 준다
- 표시된 행을 모두 [확인]하거나 고치고, "원본 결과지와 대조해 확인했습니다"를 체크해야 다음으로 넘어간다
- 데모·직접 입력은 막지 않는다
- 헤드리스 Chrome 으로 두 UI 모두 확인: 처음 막힘 → 체크만 해도 막힘 → 행 확인+체크 시 열림 → 체크 해제 시 막힘

함께 고친 기존 버그: 화면이 OCR 결과를 몇 개 필드만 골라 담아 `value_text`(`<0.15`)·`size_text`(`4.5x3`)가
사라지고 있었다. 리포트·FHIR 에서 미만 표기와 팽진 크기가 빠졌다. 원래 필드를 모두 남기도록 고쳤다.
